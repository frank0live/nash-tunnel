# 🚀 Nash Tunnel

**اسکریپت و پنل وب مدیریت تونل معکوس (GRE، FRP و Backhaul Xray) همراه با واچ‌داگ، بنچمارک و فِیل‌اور خودکار**

جایگزینی متن‌باز، سبک و رایگان برای پنل‌های تجاری؛ **بدون نیاز به لایسنس، بدون قفل و بدون محدودیت در تعداد سرور.**

## ✨ ویژگی‌های کلیدی

- **پشتیبانی چندگانه از پروتکل‌ها:** پیاده‌سازی همزمان یا مجزای تونل‌های سطح شبکه (`GRE`)، معکوس (`FRP`) و ترافیک مخفی (`Xray REALITY Backhaul`).
- **پنل وب اختصاصی و بدون وابستگی:** بک‌اند نوشته‌شده با کتابخانهٔ استاندارد پایتون (بدون نیاز به نصب پکیج‌های اضافی یا `pip`) با رابط کاربری فارسی و راست‌به‌چپ (RTL).
- **مانیتورینگ و واچ‌داگ هوشمند:** بررسی خودکار سلامت سرویس‌ها در پس‌زمینه، ری‌استارت خودکار در صورت قطعی و ارسال گزارش لحظه‌ای به تلگرام.
- **بنچمارک و تست تأخیر:** مقایسه و رتبه‌بندی نودها بر اساس پینگ و تأخیر واقعی.
- **اجرای دوگانه (تعاملی و اسکریپتی):** قابل استفاده هم از طریق منوی گرافیکی ترمینال و هم به صورت دستورات خط فرمان (CLI) برای اتوماسیون.

## 📋 پیش‌نیازها

- سیستم‌عامل لینوکس مبتنی بر Debian یا Ubuntu (پیشنهادی: Ubuntu 20.04 به بالا)
- دسترسی `root`
- نصب بودن `python3` و `systemd` (به‌طور پیش‌فرض روی اکثر توزیع‌ها نصب است)

## ⚡ نصب سریع

برای نصب یا به‌روزرسانی، دستور تک‌خطی زیر را اجرا کنید:

</div>

```bash
curl -fsSL https://raw.githubusercontent.com/frank0live/nash-tunnel/main/install.sh | bash
```

<div dir="rtl">

> **نکته:** این اسکریپت با محیط‌های غیرتعاملی (Non-interactive) کاملاً سازگار است؛ در صورتی که داخل اسکریپت دیگری یا بدون ترمینال (TTY) اجرا شود، منو قفل نمی‌شود و راهنمای دستورات خط فرمان نمایش داده خواهد شد.

**نصب دستی و اجرای منوی تعاملی:**

</div>

```bash
git clone https://github.com/frank0live/nash-tunnel.git
cd nash-tunnel
bash nash.sh          # اجرای منوی تعاملی
```

## 🛠 دستورات خط فرمان (CLI)

علاوه بر منوی تعاملی، می‌توانید تمام عملیات را مستقیماً با دستورات زیر اجرا کنید:

| دستور | عملکرد |
|---|---|
| `bash nash.sh status` | نمایش گزارش کامل سلامت سرور (CPU، RAM، دیسک، وضعیت سرویس‌ها و تونل) |
| `bash nash.sh install-iran` | نصب و راه‌اندازی سمت سرور ایران (GRE Server + `frps` + پنل وب) |
| `bash nash.sh install-foreign` | نصب و راه‌اندازی سمت سرور خارج (GRE Client + `frpc` + پنل وب) |
| `bash nash.sh backhaul` | پیکربندی سمت سرور Backhaul (مبتنی بر Xray REALITY) |
| `bash nash.sh backhaul-client ...` | پیکربندی سمت کلاینت Backhaul |
| `bash nash.sh watchdog` | نصب و بازنشانی سرویس واچ‌داگ (بررسی در بازه‌های ۶۰ ثانیه‌ای) |
| `bash nash.sh benchmark` | تست پینگ و تأخیر تمامی نودها و رتبه‌بندی آن‌ها |
| `bash nash.sh failover` | تعویض نود فعال به سالم‌ترین نود (دستی یا خودکار) |
| `bash nash.sh panel` | ری‌استارت کردن سرویس پنل وب |
| `bash nash.sh uninstall` | حذف کامل اسکریپت، سرویس‌ها و تنظیمات |

## 🖥 پنل مدیریت وب

پس از اتمام نصب، پنل مدیریت روی پورت پیش‌فرض در دسترس خواهد بود:

- **آدرس ورود:** `http://SERVER_IP:8090` (روی سرور خارج پنل روی پورت `8091` بالا می‌آید)
- **رمز عبور:** در پایان مراحل نصب به‌صورت تصادفی (۱۴ کاراکتر) تولید و در ترمینال نمایش داده می‌شود.
- **تغییر رمز عبور:** اجرای دستور `bash nash.sh` و انتخاب **گزینهٔ ۹**.
- **امکانات پنل:**
  - پایش زندهٔ مصرف منابع سرور (CPU، RAM، دیسک و Uptime)
  - مشاهدهٔ وضعیت سرویس‌ها با قابلیت ری‌استارت تک‌کلیکی
  - تست زندهٔ اتصال نودها و مشاهدهٔ لاگ‌های سیستم
  - رابط کاربری کاملاً فارسی و راست‌به‌چپ (RTL)

---

## 👁 سرویس واچ‌داگ (Watchdog)

واچ‌داگ یک تایمر `systemd` است که هر **۶۰ ثانیه** وضعیت سرویس‌های `nash-panel`، `nash-frps`، `nash-frpc`، `nash-backhaul` و همچنین اینترفیس شبکهٔ `nash-gre` را بررسی می‌کند.

در صورت توقف یا اختلال در هر یک از سرویس‌ها، واچ‌داگ به‌طور خودکار آن را ری‌استارت کرده و گزارش عملیات را به تلگرام ارسال می‌کند. برای فعال‌سازی اطلاع‌رسانی تلگرام، مقادیر توکن ربات و Chat ID را در فایل `/etc/nash/config.json` وارد کنید.

## 📂 ساختار فایل‌ها و مسیرها

</div>

```text
nash.sh                 # اسکریپت اصلی (نصب، مدیریت و منوی تعاملی)
install.sh              # اسکریپت نصب سریع تک‌خطی
panel/panel.py          # بک‌اند پنل وب (پایتون استاندارد، بدون وابستگی خارجی)
web/index.html          # فرانت‌اند پنل وب (تک‌فایل، راست‌به‌چپ)
systemd/                # فایل‌های نمونهٔ سرویس‌های systemd
/etc/nash/config.json   # تنظیمات پایه (پورت، نودها، اطلاعات تلگرام)
/etc/nash/panel.json    # هش رمز عبور پنل و مدیریت سشن‌ها
/etc/nash/frps.toml     # پیکربندی سرور FRP
/etc/nash/frpc.toml     # پیکربندی کلاینت FRP
/etc/nash/backhaul/     # فایل‌های پیکربندی هستهٔ Xray
```

## 🔒 امنیت

- **هش رمز عبور:** رمز پنل با الگوریتم `PBKDF2-SHA256` و ۱۲۰٬۰۰۰ دور تکرار (Iteration) هش می‌شود.
- **مدیریت نشست (Session):** کوکی‌ها دارای پرچم‌های امنیتی `HttpOnly` و `SameSite=Strict` بوده و پس از ۱۲ ساعت منقضی می‌شوند.
- **احراز هویت تونل:** توکن‌های FRP و کلیدهای GRE کاملاً تصادفی تولید می‌شوند.
- **سطح دسترسی:** تمامی فایل‌های پیکربندی حساس دارای مجوز دسترسی محدود (`chmod 600`) هستند.

> **توصیه امنیتی:** پیشنهاد می‌شود پنل وب را پشت وب‌سرور Nginx به همراه گواهی SSL/TLS قرار دهید، یا دسترسی به پورت `8090` را از طریق فایروال فقط به IP خودتان محدود کنید:

</div>

```bash
ufw allow from YOUR_IP to any port 8090
```

## 🔧 عیب‌یابی (Troubleshooting)

برای مشاهدهٔ راه‌حل هر مشکل، روی عنوان آن کلیک کنید:

<details>
<summary><b>۱. منو پشت سر هم خطای <code>! invalid choice</code> چاپ می‌کند</b></summary>
<br>

این اتفاق زمانی رخ می‌دهد که ورودی استاندارد (`stdin`) به ترمینال متصل نباشد (مثلاً هنگام اجرای مستقیم با `curl ... | bash` یا اجرا از داخل ابزارهای اتوماسیون).
از نسخهٔ `1.0.1` به بعد، اسکریپت به‌طور خودکار به `/dev/tty` متصل می‌شود. اگر در محیطی بدون ترمینال هستید، از دستورات غیرتعاملی استفاده کنید:

```bash
bash nash.sh status
bash nash.sh install-iran
bash nash.sh install-foreign
```
</details>

<details>
<summary><b>۲. خطای <code>Job for nash-gre.service failed ... invalid value for "key"</code></b></summary>
<br>

کلید تونل GRE باید حتماً **عددی** باشد. در نسخه‌های قدیمی، کلید شامل حروف نیز می‌شد که باعث توقف فوری سرویس می‌گردید. برای رفع مشکل، کلید قبلی را پاک کرده و کانفیگ را مجدداً بسازید:

```bash
rm -f /etc/nash/gre.key
bash nash.sh install-iran      # کلید عددی جدید تولید و چاپ می‌شود
```

سپس همان کلید جدید را در سرور خارج وارد کنید. توجه داشته باشید که مقدار کلید در هر دو سرور باید کاملاً یکسان باشد؛ در غیر این صورت اینترفیس بالا می‌آید اما ترافیکی عبور نخواهد کرد:

```bash
cat /etc/nash/gre.key                  # بررسی یکسان بودن کلید در دو سرور
ip -d link show nash-gre | grep ikey   # مشاهده کلید فعال روی اینترفیس شبکه
```
</details>

<details>
<summary><b>۳. خطای <code>Job for nash-backhaul.service failed</code> یا <code>invalid "shortIds[0]"</code></b></summary>
<br>

مقدار `shortId` در پروتکل REALITY باید در مبنای هگزادسیمال (`0-9a-f`) باشد. برای رفع این خطا، کافی است کانفیگ را از طریق **گزینهٔ ۴ منو** مجدداً بسازید.
</details>

<details open>
<summary><b>۴. پینگ TCP برمی‌گردد ولی دیتا عبور نمی‌کند (تأخیر واقعی یا Real Delay روی <code>-1ms</code> می‌ماند)</b></summary>
<br>

اگر ترافیک را در سرور خارج به سرویسی روی لوکال‌هاستِ همان سرور فوروارد می‌کنید (مانند پنل `3x-ui`، سرویس `sshd` یا `nginx`) اما سرویس مقصد هیچ درخواستی دریافت نمی‌کند، ایراد از پیکربندی شما نیست.

**علت فنی:**
از نسخهٔ `v26.4.17` هستهٔ Xray (طبق [PR #5947](https://github.com/XTLS/Xray-core/pull/5947)) خروجی `freedom` برای جلوگیری از حملات SSRF به‌طور پیش‌فرض تمامی آدرس‌های Private و Reserved (از جمله `127.0.0.1`) را مسدود (Blackhole) می‌کند. کلید پیکربندی `finalRules` که برای باز کردن استثنا به آن نیاز داریم، از نسخهٔ `v26.5.9` ([PR #6027](https://github.com/XTLS/Xray-core/pull/6027)) در دسترس است؛ بنابراین روی نسخه‌های میان این دو، استثنا بی‌صدا نادیده گرفته می‌شود و راهی جز به‌روزرسانی Xray وجود ندارد. در نسخه‌های `1.0.1` و قدیمی‌ترِ این اسکریپت، خروجی سرور خارج به‌صورت یک `freedom` ساده تعریف می‌شد:

```json
"outbounds": [{ "protocol": "freedom" }]
```

در نتیجه، هرگونه فوروارد به پورت‌های لوکال سرور خارج بی‌صدا مسدود می‌شد. نشانهٔ این مشکل نیز گمراه‌کننده است: پینگ TCP برقرار است و `curl telnet://` متصل می‌شود، اما تست Real Delay با تایم‌اوت مواجه شده و در سطح لاگ `warning` نیز خطایی ثبت نمی‌شود. تنها با تغییر سطح لاگ به `info` پیغام زیر مشاهده می‌شود:

```text
proxy/freedom: blocked target: tcp:127.0.0.1:2053, blackholing connection for 47s
```

(روی `v26.4.17` که `finalRules` ندارد، پیام لاگ کوتاه‌تر است: `blocked target IP: 127.0.0.1`)

*(نکته: مقصد `dokodemo-door` تعریف‌شده در سرور ایران، در انتهای تونل و روی سرور خارج تفسیر می‌شود؛ بنابراین استفاده از `127.0.0.1` کاملاً صحیح است و نیازی به وارد کردن IP عمومی سرور خارج نیست).*

**راه‌حل:**
از نسخهٔ `1.0.2` اسکریپت، این محدودیت برای لوکال‌هاست برطرف شده و بخش `outbounds` سرور خارج به شکل زیر تولید می‌شود (نیازمند Xray نسخهٔ `v26.5.9` یا بالاتر؛ نصب‌کنندهٔ یک‌خطی همیشه آخرین نسخه را می‌آورد):

```json
"outbounds": [{
  "protocol": "freedom",
  "settings": {
    "finalRules": [
      {"action": "allow", "network": "tcp", "ip": ["127.0.0.1/32", "::1/128"]}
    ]
  }
}]
```

با این تنظیم، فقط دسترسی به لوکال‌هاست مجاز شده و سایر رنج‌های خصوصی همچنان ایمن و مسدود باقی می‌مانند. اگر کانفیگ خود را با نسخه‌های قدیمی‌تر ساخته‌اید، در سرور خارج دستورات زیر را اجرا کنید تا کانفیگ بازسازی شود:

```bash
bash nash.sh backhaul
systemctl restart nash-backhaul
```

یا می‌توانید بلوک `settings` بالا را به‌صورت دستی به فایل `/etc/nash/backhaul/server.json` اضافه کرده و سرویس را ری‌استارت کنید.

برای بررسی زندهٔ لاگ و اطمینان از رفع مشکل نیز می‌توانید از دستور زیر کمک بگیرید:

```bash
sed -i 's/"loglevel": "warning"/"loglevel": "info"/' /etc/nash/backhaul/server.json
systemctl restart nash-backhaul && journalctl -u nash-backhaul -f
```
</details>
